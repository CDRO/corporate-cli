# Milestone 39: v1 / v2 / Later Prioritization

## Goal
Group the implementation tickets into priority levels so the first build remains small while the roadmap stays clear for future changes.

## v1: must-have for the first useful version
- Ticket 01: project skeleton
- Ticket 02: basic CLI parsing
- Ticket 03: default transformation pipeline
- Ticket 04: rule-based harsh phrase replacement
- Ticket 05: lexicon and misspelling cleanup
- Ticket 06: `etaroproc` inverse mode
- Ticket 07: tests for README examples
- Ticket 08: config and user defaults
- Ticket 20: release quality gates

## v2: important for usability and flexibility
- Ticket 09: authentication flow for AI mode
- Ticket 10: AI provider abstraction
- Ticket 11: AI prompt templates
- Ticket 12: fallback and retry logic
- Ticket 13: provider switching and profile presets
- Ticket 14: chunking and long-input support
- Ticket 15: result validation and output safety
- Ticket 16: style templates and user profiles
- Ticket 18: usage tracking and cost visibility
- Ticket 19: logout and credential refresh

## Later: optional or advanced features
- Ticket 17: local model support
- Ticket 21: additional advanced prompt tuning and custom templates
- Ticket 22: advanced personalization and stored user learning
- Ticket 23: remote analytics collection
- Ticket 24: plugin ecosystem or custom rewrite rules file
- Ticket 25: broader language and dialect support

## Notes
The v1 list prioritizes deterministic behavior and safe core functionality. The v2 list adds AI and account flows, while later items focus on advanced, optional enhancement and scale.
